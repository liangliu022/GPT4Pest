# GPT4Pest: Reproducibility Repository

This repository provides an implementation scaffold and data-organization protocol for:

**Knowledge-Enhanced Multimodal Learning via Semantic Alignment for Fine-Grained Agricultural Pest Recognition**

The code is organized around the workflow described in the manuscript:

1. Curate the CPest image collection and create source-image-level train/validation/test splits.
2. Generate class-conditioned pest descriptions for **training images only** using MiniGPT-4 (or import descriptions generated by the original MiniGPT-4 run).
3. Encode descriptions with BERT and cache text embeddings.
4. Train a ResMLP-based visual classifier with classification and image-to-text contrastive alignment losses.
5. Evaluate the visual classifier. Inference does not require MiniGPT-4 or BERT.

> **Important reproducibility notice**
>
> This is a structured release scaffold based on the manuscript, not a claim that every original experimental implementation detail has been recovered. The code specifies the exact ResMLP variant, projection dimension, temperature `tau`, alignment weight `lambda`, BERT checkpoint, full optimizer settings, random seeds, or diffusion model/version and configuration. These are explicit configuration fields.
>
> The repository intentionally does not include third-party CPest images, generated image files, pretrained weights, or fabricated semantic descriptions. Their use and redistribution depend on source-site licenses and the authors' actual records.

| Item | Manuscript |
|---|---|
| Dataset | CPest, 40 categories |
| Original curated images | 4,510 |
| Reported total after augmentation | 18,942 image files |
| Split | 8:1:1 at original source-image level, before augmentation |
| Augmentation | affine transforms, random crop, rotation, scaling, horizontal flip, diffusion-model-based enhancement |
| Description generator | MiniGPT-4 |
| Text encoder | pretrained BERT; text embeddings reported as precomputed/cached |
| Visual encoder | ResMLP-based |
| Loss | cross-entropy + `lambda *` image-to-text InfoNCE |
| Optimizer | SGD |
| Learning rate | 0.0001 |
| Batch size | 8 |
| Epochs | 200 |
| Hardware | NVIDIA GeForce RTX 3090 GPU(s) |
| Inference | visual branch only |

The paper reports 95.54% accuracy. This repository does not reproduce or assert that result until the original data, model configuration, and training protocol are supplied and the experiment is rerun.

## 1. Environment

Tested design target: Python 3.10+, PyTorch 2.x, CUDA-compatible installation.

Install PyTorch according to the CUDA version on the target machine, then:

```bash
pip install -r requirements.txt
```

For exact reproduction, record the actual versions of Python, PyTorch, CUDA, timm, transformers, Pillow, NumPy, scikit-learn, and the MiniGPT-4 environment.

## 2. Data preparation

Read `data/README.md` and `docs/DATA_CARD.md` before preparing data.

Create `data/metadata/images.csv` using the schema in `images_template.csv`:

- `image_id`: stable unique identifier for the original source image.
- `image_path`: local path to the image.
- `label`: exact class label used by the manuscript.
- `source_id`: identifier for the original source image. All transformed versions must retain the same source ID.
- `source_url`: original URL, if legally and practically recordable.
- `split`: leave blank before running the split script.
- `is_augmented`: `false` for original images; `true` for derivatives.
- `parent_image_id`: original image ID for an augmented derivative; blank for original images.

Run:

```bash
python scripts/make_splits.py \
  --input data/metadata/images.csv \
  --output-dir data/splits \
  --seed 42
```

The split script splits **unique original source IDs**, then assigns all records sharing a source ID to the same split. For strict paper reproduction, replace the example seed with the original seed if known. If the original split assignments exist, use those rather than regenerating them.

Augmented images should be added only after the source-level split and only to the training partition. Do not create derivatives of validation/test images. Do not count transformed/synthetic images as independent biological observations.

## 3. Class-conditioned description generation

The manuscript reports the prompt:

> Describe the [pestname] in this image in detail.

The actual generation environment for MiniGPT-4 is installation- and checkpoint-specific. Therefore, this repository supplies the prompt convention and a CSV interchange format rather than pretending to include an unverified MiniGPT-4 API implementation.

Generate descriptions for training images only, then save:

`data/metadata/descriptions.csv`

with columns `image_id,description,generator,model_version,prompt_version,generated_at`.

A description must be linked to the image ID that generated it. Keep model version, prompt, decoding settings, and generation date in the metadata. Do not generate training descriptions using validation/test labels or include validation/test descriptions in the training cache.

## 4. Encode text with BERT

```bash
python scripts/encode_text.py \
  --descriptions data/metadata/descriptions.csv \
  --output data/cache/text_embeddings.pt \
  --model-name bert-base-uncased
```

`bert-base-uncased` is a placeholder default, not a verified identification of the checkpoint used in the paper. Replace it with the exact checkpoint and revision used in the original experiments. The script uses mean pooling over non-padding tokens. If the original implementation used CLS pooling or another pooling rule, change it accordingly and document it.

## 5. Train

Edit `configs/default.yaml` first. In particular, confirm the exact ResMLP architecture, BERT checkpoint, projection dimension, `tau`, `lambda_align`, optimizer momentum/weight decay/scheduler, image size, and random seed.

```bash
python scripts/train.py --config configs/default.yaml
```

The training implementation assumes each training image has one cached text embedding. The visual encoder and projection heads are optimized jointly with the classifier. The BERT text encoder is not loaded in the training loop because the manuscript says text embeddings were precomputed and cached. This design must be changed if the original code fine-tuned BERT online.

## 6. Evaluate

```bash
python scripts/evaluate.py \
  --config configs/default.yaml \
  --checkpoint outputs/best.pt \
  --split data/splits/test.csv
```

Evaluation uses the visual encoder and classification head only. Report accuracy, macro precision, macro recall, macro F1, and per-class metrics. Preserve the exact test split and do not tune hyperparameters against it.
